# ATDR v0.8 Detection Generalization Validation

## Status

ATDR v0.8 adds a controlled anti-overfitting validation path for the existing safe scenario catalog. It generates synthetic defensive log variants, runs detection in a temporary SQLite database by default, and reports whether expected detection behavior still holds when IPs, timestamps, ports, session IDs, byte counts, and benign noise are varied.

This is not offensive testing, production certification, or real device validation.

## What Works

- Safe scenario variants are generated by `atdr/scripts/generate_detection_variants.py`.
- Variants are written under ignored `demo_exports/detection_variants/`.
- Generalization validation is run by `atdr/scripts/run_detection_generalization_suite.py`.
- Reports are written under ignored `demo_exports/detection_generalization/`.
- The suite uses a temporary in-memory SQLite database by default.
- The suite validates false positives, false negatives, parser behavior, evidence quality, deduplication where relevant, and response safety.
- The React Overview page shows the latest compact generalization status from `/api/dashboard/validation-summary`.

## Safety Boundaries

- Generated logs are synthetic defensive records only.
- No exploit payloads, offensive instructions, or real attack execution are generated.
- Response actions remain simulated and analyst-approved.
- The suite checks that no response actions are created.
- Real firewall blocking remains disabled.
- ML remains decision support only.
- Reports and generated variants must not be committed.

## Commands

Generate variants only:

```powershell
.\.venv\Scripts\python.exe -m atdr.scripts.generate_detection_variants --scenario port_scan_like_traffic --variants 3 --pretty
```

Run the full generalization suite safely against a temporary database:

```powershell
.\.venv\Scripts\python.exe -m atdr.scripts.run_detection_generalization_suite --all --variants 5 --pretty
```

Run a fast focused check:

```powershell
.\.venv\Scripts\python.exe -m atdr.scripts.run_detection_generalization_suite --scenario port_scan_like_traffic --scenario normal_web_dns_quic_traffic --variants 2 --pretty
```

Only write variants to the current dashboard database when intentionally inspecting a generalization run in React:

```powershell
.\.venv\Scripts\python.exe -m atdr.scripts.run_detection_generalization_suite --scenario port_scan_like_traffic --variants 2 --write-to-current-db --pretty
```

## Report Interpretation

The JSON/Markdown report summarizes:

- scenario families tested
- generated variant count
- passed/failed variants
- false positives
- false negatives
- attack types observed
- rule/anomaly/supervised/hybrid contribution signals
- response-action safety checks

Passing generalization validation means the current detection logic is less dependent on one fixed sample file. It does not mean ATDR is production-ready.

## Known Limits

- Variants are synthetic and cannot replace controlled real firewall/router forwarding validation.
- The suite validates expected behavior families, not every possible log format.
- Detection thresholds should only be tuned when failures are reproducible and explainable.
- Generated reports can grow over time and should stay ignored under `demo_exports/`.

## Next Recommended Phase

Use v0.8 results as a stable lab checkpoint, then continue with controlled real-source validation when real or simulated router/firewall forwarding is available.
