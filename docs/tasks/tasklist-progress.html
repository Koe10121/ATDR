T6. Decision

The v5.64 implementation is complete and its candidate decision is fail-closed. No anomaly candidate qualified, no holdout was consumed for candidate selection, and no artifact or authoritative state changed. The full verification matrix first ran green on 2026-09-18.

A subsequent direct code-review pass (2026-09-19) found and fixed real defects: two in the uncommitted v5.64 module (a dead duplicate strategy branch, a legacy-diagnostic schema-key mismatch — neither affected any gate, ranking, or reported number) and a substring-matching zone-classification bug that misread Palo Alto's default untrust zone as an inside zone. The zone bug was first found in the published, alert-authoritative rule engine (atdr/app/detection/rules.py, feeding false context into six rules including the two highest-value ones — C2 beaconing, exfiltration suspicion) — and a repository-wide search then found the identical defect independently reimplemented in two more places: the analyst-facing explanation engine (explanations.py) and, most significantly, alert grouping itself (services/detection_service.py's _group_key, which had zero prior test coverage). All three are fixed by consolidating to one canonical, now-public implementation, covered by 7 new regression tests, and documented (v5.64 fixes in docs/changes/T1_T20_V5_64_WINDOW_AWARE_ADVISORY_ANOMALY_REDESIGN.md; the zone-classification fix in docs/changes/T1_T20_RULE_ENGINE_ZONE_CLASSIFICATION_FIX.md).

Two further pieces of work were completed the same day at the project owner's direction:

1. Real, opt-in, host-scoped response enforcement. The dashboard's block/unblock workflow — previously fully simulated — now has a genuine Windows Firewall connector (atdr/app/services/windows_firewall_connector.py), selected deliberately over a real network-firewall connector after review of what already existed. It is off by default in every shipped profile, requires an explicit two-key opt-in, is refused outside a local/lab environment or off Windows, never marks a block active unless enforcement genuinely succeeded, never marks an unblock complete unless removal genuinely succeeded, always protects the ATDR host's own address(es), and supports capped timeouts with lazy expiry sweeping. See docs/changes/T1_T20_RESPONSE_REAL_ENFORCEMENT.md. 2. AI Assistant IPv6 redaction gap. A direct review of the Assistant's privacy-critical redaction path found that IP_PATTERN was IPv4-only, duplicated independently across six files — including two acceptance quality-gates that would have silently certified an IPv6 leak as privacy-passing. Consolidated to one canonical IPv4+IPv6 pattern. See docs/changes/T1_T20_ASSISTANT_IPV6_REDACTION_FIX.md.

The complete matrix was re-run in full after every fix and passed: taskboard, Ruff, compileall, Alembic (including the new additive migration), full backend suite (1158 passed, 1 skipped), frontend lint/build/Playwright (45 passed, 1 skipped), controlled source and layered detection validation (unchanged safety signature), Assistant QA, replay smoke, performance smoke, repository surface audit, security acceptance, and the independent release gate. All four pieces of work (v5.64, the rule-engine fix, real response enforcement, and the Assistant redaction fix) are approval-ready pending a separately approved commit/push decision.
